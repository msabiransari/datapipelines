Client setup

Add an MCP server to Claude Code, Cursor or Copilot

This page sets up one particular MCP server, datapipelines.co's, the one that puts your SQL databases behind role-checked, audited, read-only-by-default credentials. It is not a general directory of MCP servers. If you came looking for how the mcp add mechanics work, they are the same either way, and the four steps below are the whole job.

Step 1

Have a server to point at

Self-hosted, so the first step is yours. The quickstart brings up the app, Postgres, Redis and a seeded demo with real NYC taxi data in one command:

./app.sh --start --demo nyc,trade,lake

For your own databases, register a datasource per engine. Postgres, SQL Server, SQLite, DuckDB, H2 and dp-lake ship in the published image; you supply the MySQL and Oracle drivers, because of their licenses. Engine-by-engine details.

Step 2

Create your MCP key on the Keys page

Sign in, open the Keys page, and choose New API key: pick the kind mcp and the role the agent should carry. The dialog offers exactly the roles whose permissions are a subset of yours. Create shows the full key once, and the server keeps only a hash afterwards, so copy it straight into the client config in step 3. Rotation later is the same page: revoke the key, create another.

The key holds the role you gave it, as an identity of its own. What the agent may do, by the role the key carries:

What the key may do, by the role it carries.
The key's roleThe agent may…
Authorcreate and update pipelines and templates, run them, probe SQL, preview rows and publish endpoints
Promoterread released-and-newer pipelines and templates, and datasource schemas. That is the promotion reviewer's reach, nothing executable
Workspace admineverything an author's key reaches, plus administering the workspace itself. No key is ever a super admin, so instance administration stays out of reach

Administration of the instance stays with signed-in people; no key can hold it. The key's role is fixed at creation: your later role changes do not flow into it.

Rotating means revoking the key on the Keys page and creating another under a fresh name; revocation takes effect within about a minute. There is no shared password to rotate.

Step 3

Paste one config block

Every client needs the same two facts: the endpoint POST {host}/mcp, over Streamable HTTP, and an API key in DP-API-Key, or in Authorization: Bearer dpk_… for clients that can only set the standard header. Both route through the identical validation path. Browser session cookies are rejected on /mcp, deliberately.

The URL and the header are ours, and specified above. The file names and the JSON shape around them belong to each client and change when its vendor changes them. Check the client's own documentation if a block here is refused, and tell us so we can fix the page.

Step 4

Check that the tools came back

Ask the agent to list its tools. A working connection reports 30 from this server, starting with pipelines_list and datasources_list. Nothing else needs configuring: capabilities come from the standard initialize handshake.

If it does not connect

  • 401 auth.api_key.missing: the header did not arrive. Check the header name, and that the client sends headers at all on HTTP transports.
  • 401 auth.api_key.invalid or auth.api_key.expired: wrong, revoked or expired.
  • 401 auth.principal_deactivated: the key's identity or its MCP-key creator is deactivated. Ask an administrator to reactivate the account.
  • auth.role_required, as the tool's result: the key is real and the role it carries does not reach what the agent tried. The key acts at its own role: to widen its reach, create another key with a wider role, which the dialog offers only when your own role reaches that far.
  • Silent rejection of a browser session: expected. /mcp takes API keys only; a cookie will never work there.
