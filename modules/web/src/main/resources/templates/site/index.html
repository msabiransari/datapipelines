Why you can put these numbers in front of a customer

You see every step

Each step of the build shows the rows it produced, and the logic is readable SQL — not code you have to trust.

Nothing goes live on its own

One human release, every time. A released version is immutable; a partner's key is bound to its path.

You can rerun and compare

Every run is recorded with its inputs, so a number you doubt can be reproduced, not argued about.

Automatic cross-checks between sources are on the roadmap. Today the check is yours — and it is a five-minute one, because everything is on one screen.

And the agent records what it learns about your data — a unit, a time zone, what a code means — with the query that proved it, so the next question starts from evidence. The learned semantic layer →

The demo is the quickstart

Real data, one command, three families

./app.sh --start --demo nyc builds the jar, downloads the published sample set, verifies every checksum, restores the databases and seeds worked examples into your workspace at first login. The demo data, table by table — what loads, where it is from, and its licences.

  • nyc — taxi trips on Postgres, weather on MySQL, a reference database on SQLite: three engines in one run.
  • trade — US trade flows on DuckDB, world mirror statistics on MySQL, exchange rates on SQLite: --demo nyc,trade.
  • lake — 470 million rideshare trips as Parquet on S3, read in place; nothing downloads: --demo nyc,trade,lake.

Then ask it the sentence at the top of this page — or your own.
