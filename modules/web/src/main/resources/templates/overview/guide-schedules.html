New schedule

How to create one

  1. Pick the pipeline to run. It needs a current version to follow; each run uses whatever version is current then, with the parameter values you give.
  2. Set the cron pattern and its timezone — the form previews the next occurrences — and the missed-run policy: skip records missed occurrences, latest catches up the newest one.
  3. Choose who is told about which events. The settings are saved with the schedule; scheduler mail is not enabled yet, so nothing sends.

New schedule opens the Schedules list, where the form is. Your role reads schedules; an author or a workspace admin creates and changes them.

A schedule runs a pipeline's current version at the times a cron pattern names, in the timezone you choose, as the system identity rather than as the person who saved it. Every firing is recorded as a run, so you can see what ran, what was skipped and why. A person can pause a schedule, and it blocks itself when a run's outcome is unknown or something must be fixed, until someone unblocks it.
