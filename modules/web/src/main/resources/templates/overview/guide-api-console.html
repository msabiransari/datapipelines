  1. Release the read-only pipeline you want served: a published path runs its released version.
  2. Copy the prompt, fill in the bracketed parts and give it to a connected agent. It publishes the path and reads it back.
  3. Then a workspace admin associates a key with the path on the Keys page — the agent's part ends at publishing.

Copying puts the text on your clipboard and nothing else: it sends no request and grants no access. Your agent works with the permissions of its own MCP key. Your role here does not publish endpoints, so copy the request for a collaborator who can.

A released, read-only pipeline can be published at a stable URL under /api/<category>/<version>/…, so an application fetches its rows with one GET. Every call carries a key in the DP-API-Key header, and an API key reaches only the paths it is associated with. Agents connect through the MCP server instead, with a key of their own.

  1. Publish a path. A released, read-only pipeline is published at a path by your agent (endpoints_create) or by a program calling POST /api/v1/endpoints — authors and admins only. There is no form for it in the app.
  2. Create and associate a key. A workspace admin creates an API key on the Keys page and associates it with the path; no agent can create one. Manage API keys Ask a workspace admin for this step.
  3. Call it. An application sends GET /api/<category>/<version>/<path> with the key in the DP-API-Key header. An agent connects with the MCP server card below.

Call counts are not recorded anywhere in this system, so this page shows none.
