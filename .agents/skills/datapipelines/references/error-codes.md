# Error codes you will meet

Open when a tool answered `isError: true` and you need the code's meaning and the response it calls for.

Part of the `datapipelines` skill — the operating core is `SKILL.md` beside this file.

| Code | Meaning | Agent response |
|---|---|---|
| `auth.api_key.missing` / `auth.api_key.invalid` | Credential problem — absent, unknown, revoked or expired | Ask the user for a fresh key |
| `auth.principal_deactivated` (401) | The key's OWNER has been deactivated; the key itself is intact and comes back when an administrator reactivates the account | Nothing to retry and no key to ask for — say the account is deactivated and stop |
| `auth.scope.insufficient` | Key lacks the required scope | Ask for a broader key, or change what you asked |
| `auth.role_required` | Your key's issuer lacks the ROLE for this action in this workspace — a different axis from scope, and a broader key will not help | Ask a workspace admin to grant the role, or do the part you can do. `details.required` / `details.held` name both sides |
| `auth.key_issuer_role_lost` | The key was valid; its issuer's role changed | Retrying will never work — a NEW key from someone who still holds the role is the fix. Say so plainly; do not loop |
| `datasource.grant_required` / `datasource.not_found` | The datasource is not granted to your workspace, or does not exist — deliberately indistinguishable | `datasources_list` is the truth. **Do not guess names**: an ungranted datasource is invisible, so a guess can never succeed and each one is noise |
| `datasource.table_not_found` (404) | The table is not in the namespace's catalog listing — the message names the nearest listed table | Check `datasources_get_tables` for the spelling — read the name from the listing, never probe a guess |
| `datasource.table_forbidden` (403) | The table exists, but the datasource's credentials cannot read it | Not a typo to hunt — ask the operator for a grant |
| `datasource.lake_table_not_found` (404) | On a LAKE datasource, the table is not REGISTERED in that namespace — `_get_columns`, `_get_table_stats` and the lake-table writes all answer it; `details.suggestion` names the nearest registered table when one is close | Read the name from `datasources_get_tables` and use it exactly; a lake table exists only when its registry row does — never retry a spelling you guessed |
| `workspace.not_found` | The workspace you addressed does not exist for you: unknown, not yours, or deactivated — one answer for all three | Nothing to retry and nothing to probe. Your key's workspace is fixed at issuance; ask the user for a key in the workspace they mean |
| `auth.key_workspace_inactive` (404) | Your key's pinned workspace has been DEACTIVATED — not-found on every surface, keys included (ruled 2026-09-14); the distinct code reveals nothing (you are a member of that workspace by construction) and is what an operator greps for | Every tool will refuse until a super admin reactivates it. Do not retry and do not ask for a different key in the same workspace; say which workspace is deactivated and stop |
| `pipeline.validation.*` (`cycle_detected`, `dangling_dependency`, `duplicate_node_id`, `parameter_precision_missing`, …) | Pipeline JSON is invalid | Fix the JSON — never retry as-is |
| `pipeline.validation.check_invalid` | A `checks[]` entry is malformed — bad or duplicate id, blank name, `tempdb`/unknown datasource, `${}` in the SQL, an undeclared `:name` bind, or a broken `expected` | Fix the entry the `path` names (`checks[i].field`); a check binds DECLARED parameters only, and its `expected.kind` is `value` / `range` / `rows` |
| `pipeline.check.failed` | A human's release hit a failing or erroring check run | Not yours to override — `details.checks` names the failing checks with expected/observed; fix the pipeline or the data and say which, or hand the decision to the human |
| `pipeline.validation.calculator_output_shape_mismatch` | The CALCULATOR node's key mapping does not fit its kind: `context_keys` on a single-output kind, `context_key` on a multi-output one, both fields, or neither | One field per kind shape: `context_key` for a single-output kind, `context_keys` (every declared output mapped) for a multi-output one — `calculators_list` says which |
| `pipeline.validation.calculator_output_unknown` | A `context_keys` entry names an output the kind does not declare | `details.known_outputs` is the truth — map those names, never guess |
| `pipeline.validation.calculator_outputs_incomplete` | A declared output of a multi-output kind is not mapped in `context_keys` | Map EVERY output in `details.missing` and the rest — no partial mappings |
| `pipeline.execution.calculator_keys_partial` | You supplied some but not all of a multi-output node's keys at execute time | All-or-nothing per node: supply every key (`details.missing` names the rest) or none and let the node compute |
| `pipeline.validation.table_not_learned` | A `pipelines_create`/`pipelines_update` named a table whose columns YOUR key never read — `details.tables` lists each `{datasource, table, clearing_call}` | Make the named `datasources_get_columns` calls (learn before you write), then save again — stats are advice, columns are the requirement |
| `pipeline.validation.door_unacknowledged` | The pipeline's door is two raw DATE parameters with no period parameter and no window calculator | Rule 13: use a period parameter or an anchor date with a CALCULATOR window. Pass `door_acknowledged: true` ONLY when the question truly fixes two dates — never to silence the refusal |
| `pipeline.execution.template_unrendered` | You execute a draft whose pinned draft template changed after your last render of it — `details.templates` names each `{id, version, updated_at, last_render}` | `templates_render` each named template, then execute again — the run is not its render |
| `template.validation.*` (`syntax_error`, `dangerous_construct`, …) | Template body rejected | Fix the Freemarker and re-render |
| `template.not_found` / `datasource.not_found` | Reference points at nothing | Create the referenced entity or fix the id |
| `pipeline.version.conflict` | The pipeline changed after you loaded it (stale `expected_hash`) | Re-read with `pipelines_get`, rebase your edit onto the current body/hash, retry — NEVER retry blindly |
| `pipeline.version.not_draft` | Release/discard hit a pipeline with no draft | Nothing to act on for an agent — the draft was already released or discarded |
| `pipeline.version.pinned` | A live pipeline version exact-pins the version a human tried to discard/purge | A human-verb refusal — the parent named in `details` must repoint first; no agent tool discards anything |
| `pipeline.version.last_release` | A purge targeted a released version, or the entity holds non-draft versions | Purges are drafts-only and human-only — point the person at Discard (reversible) instead |
| `pipeline.version.not_eligible` | A switch targeted a discarded version (or a draft under a hardened posture) | The receiver's rollback lever refused — restore the version first, or pick a live one |
| `pipeline.authoring.disabled` / `template.authoring.disabled` | This server has authoring turned off — it is a promotion receiver | Do not retry; tell the user this server only receives promoted content. Reads, execution and import still work |
| `pipeline.validation.duplicate_name` (on update) | Your draft renames onto a taken name | Pick a different `name`; this fails at write time now, not at release |
| `pipeline.execution.datasource_unreachable` | Source DB down/bad credentials | `datasources_test` to confirm |
| `pipeline.node.query_execution_failed` | A node's SQL failed | Read `node_stats` + `executions_get` for the node error, re-render its template with the failed parameters |
| `pipeline.validation.pipeline_query_timeout_invalid` / `pipeline.validation.node_query_timeout_invalid` | The pipeline's or a node's `settings.query_timeout_seconds` is out of range, declared on a node that runs no statement (`PIPELINE`/`CALCULATOR`), or (node-level only) exceeds that same node's own `settings.timeout_seconds` | Fix the value the `path` names — never retry as-is. A node's statement budget must fit inside its own wall-clock deadline; raise `timeout_seconds` or lower `query_timeout_seconds` |
| `pipeline.node.query_timeout` | A node's query outlived its JDBC timeout (`timeout_seconds` in the detail, `source` naming which tier resolved it — `node`/`pipeline`/`datasource`/`dialect`/`application`) and was cancelled | The SQL is not wrong, it is too slow for the budget: prune on the partition column, push the filter down, stage less, split the node — see the authoring playbook. Setting this node's own `settings.query_timeout_seconds` (or the pipeline's) is the deliberate lever; raising the datasource's `query_timeout_seconds` is the last resort |
| `pipeline.node.timeout` | The NODE outlived its wall-clock budget — render through staging, whatever the driver did. `details` carries `timeout_seconds`, `elapsed_ms` and `phase` | Read the `phase`: `execute` → make the query cheaper (prune on the partition column, push the filter down); `stage` → ship fewer rows (aggregate at the source); `connect` → the pool or the network, not your SQL. Only when the scan is legitimately long, set that node's `settings.timeout_seconds` and say why. Never slice the scan |
| `pipeline.node.sql_parameter_missing` | The rendered SQL references a `:name` no pipeline parameter declares | Name a declared parameter — or interpolate structure instead |
| `template.validation.html_entity` | The body carries `&lt;`/`&gt;`/`&amp;` where a SQL operator belongs — it was HTML-escaped between you and the server | Re-send the body with the operator itself (`<=`, `>`, `&`); check how your client encodes tool arguments |
| `template.validation.freemarker_forbidden` | A transform type carried `imports`/`is_library`, or its body has a Freemarker construct (`${`, `<#`, `<@`) | Remove it — `details.rule` says which; a transform body is evaluated, never rendered |
| `template.validation.engine_unsupported` | `engine` does not match the template's type | `freemarker` iff `sql`/`html`, `none` iff `jsonata`/`javascript` |
| `template.contract_invalid` | A transform's contract block broke a rule | `details.rule` names which (`unknown_field`, `row_mode_inputs`, `empty_case_missing`, `row_case_lists_table`, …) — see `references/transforms.md` |
| `template.invariant_invalid` | An invariant does not compile, or returned non-boolean | Fix the JSONata expression named in `details.invariant` |
| `template.test_failed` | A test case failed at save or release | `details` names the case and the bounded diff, or the invariant that is false — fix the body or the expectation |
| `template.blocks_not_allowed` | `contract`/`invariants`/`tests` on an `sql`/`html` template | The blocks belong to the transform types only |
| `template.render_not_applicable` | `templates_render` (or REST `/render`) on a transform type | Use `templates_evaluate` — `details.use` says so |
| `transform.js.unavailable` | A `javascript` template was saved | Round two's engine is not shipped yet; author `jsonata` |
| `template.validation.parameter_interpolated` | A declared parameter appears inside `${}` | Write `:name` for it — bound values are never parsed as SQL |
| `result.expired` | TTL elapsed on the cursor | Re-execute and page sooner |
| `datasource.lake.table_unavailable` | A lake table's view failed to build at connect and was skipped; `details` carries `table` and the recorded `last_error` | Do not retry — the query is fine, the registration is broken. Report `last_error` to the user and let them fix or re-register the table |
| `datasource.validation.lake_no_healthy_tables` (400) | Every registered table on a LAKE datasource was refused at connect-time SQL emission, so no pool was built; the message names each table and its reason | Not a retry — the registrations are broken. Report the named tables and reasons; each is fixed with a corrected `lake_tables_register` or removed with `lake_tables_unregister` |
| `datasource.validation.property_empty` | A datasource property was `""`, whitespace, or null | Set the key to a real value or drop it entirely — empty is never stored |
| `semantics.ref_mismatch` (400) | The fact's text near-misses a listed table its `refs` do not carry — within edit distance 2 of one (`details.token` names the word, `details.suggestion` the nearest listed table). An exact listed table missing from `refs` is NOT refused: the tool adds it to the stored refs and returns `refs_added` | Name in `refs` every table the fact is about, spelled exactly as `datasources_get_tables` reports them — and if the text's spelling is the wrong one, fix the text, not the refs |
| `mcp.doc_not_found` | `docs_get` named a document the shipped skill does not carry | `docs_list` is the truth — pick a name from `details.known_docs`; `skill` is the operating core |
